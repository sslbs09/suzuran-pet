## 一、本轮已完成（核心 bug 已修、已验证）

### 1. 根因：首次启动点「同意并开始使用」后实例直接退出

- 现象：全新 userData 首启 → 弹《使用条款》→ 点「✔ 同意并开始使用」→ 实例走正常关机流程退出（`tts.log` 末尾为「语音关闭 → 停止本地服务器」），未进入引导设置窗。
- 根因在 `renderer/terms.js`：
  - 点同意 → `await agreeTerms()` → `window.close()`。
  - 但 `beforeunload` 监听器**无条件**调用 `refuseTerms()`（= `quitting=true; app.quit()`）。
  - 于是「同意后的正常关窗」被当成「拒绝」，触发 `app.quit()` → `before-quit` 清理 → 退出。
- 与 `main.js` 的 `window-all-closed`（L3918，仅 `preventDefault`，订阅后不自动退出）**无关**，不是它杀的进程。

### 2. 修复点 A：`renderer/terms.js`（加同意标志位）

```js
let agreed = false; // 点过「同意」后关窗属于正常流程，不应触发拒绝退出
document.getElementById("btn-agree").addEventListener("click", async () => {
  agreed = true;
  await window.petAPI.agreeTerms();
  window.close();
});
// 关窗 = 拒绝（已同意后的正常关窗除外）
window.addEventListener("beforeunload", () => {
  if (!agreed) window.petAPI.refuseTerms();
});
```

### 3. 修复点 B：`main.js` `openSettings()`（补 show/focus）

- 现象：首启同意后设置窗被创建但停在隐藏位（bounds `-32000`），用户看不到引导窗。
- 原因：`openSettings()` 创建 `BrowserWindow` 后没有 `show()/focus()`（对比 `createWindow()` L145 有 `win.show()`）。
- 修复：在 `settingsWin.loadFile(...)` + `attachCrashDiag(...)` 之后加：
  ```js
  settingsWin.show();
  settingsWin.focus();
  ```
- 该改动对托盘「设置」入口同样安全（已显示窗口再 show 为 no-op，focus 提到前台符合预期）。
