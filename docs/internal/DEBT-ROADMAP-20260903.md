## 一、专项审计：「系统音混进翻译过的句子」

### 结论
**系统音永远不会读日文译文。** 渲染层 `speakSystem(clean)` 的 `clean` 恒为气泡中文原文；
所谓"混"是**跨话语**的：同一轮对话里，成功的话语走 GSV 日语，失败的那句整段静音回退 →
系统音读中文（听感 = 日语句子中间/后面突然插一句机器中文音）。单条 utterance 内部不存在
混音（流式 parts 与合并段互斥，全部 GSV；`b64` 为空时 parts 必然一个都没播过）。

### 实证数据（tts.log，09-02 14:10 起）
- 「回退系统语音」共 **11 次**：09-02 下午 4 次、09-03 凌晨～清晨 7 次。
- 时间分布与三个根因完全吻合（见五点十八）：翻译缓存键不匹配（情绪语气词/前导标点）、
  lineId 情绪不匹配（60/358 句）导致现场翻译，**恰好赶上翻译 API 超时（45s×2）就整句静音**。
- 修复部署（11:57）后仅 03:59:46 残留 1 次：当时预热批次正在与播放抢同一个翻译 API
  （预热日志中成片 timeout），未入缓存的句子现场翻译再次超时。
- **预热完成后至今 0 次**——与用户"现在暂时没有"的体感一致。

### P1 语音体验（消灭最后的系统音场景）
- **O1 翻译失败 stale-while-error**：`translateToJa` 失败时回退使用已过期的旧译文（过期译文好过系统音读中文），加设置开关。这是把 R1 类残留降到最低的最后一块拼图。
- **O2 预热退避**：预热批次连续遇到 429/超时时自动拉大间隔或暂停（如连续 3 次失败 → GAP 15s→60s），给交互翻译让路；恢复后自动提速。
- **O3 硬编码台词池化**：main.js 里的钉子台词（欢迎回来/打断反应/托盘隐藏等十余句）并入 POOLS，统一获得 lineId 直查与预热。
- **O4 系统音兜底策略可配置**：设置页三选——读中文（现状）/ 静音 / 短提示音。
- **O5 单句重载补漏**：对 failed 句在设置页显式高亮 + 一键"仅重试失败项"入口（现藏在批量预加载参数里）。

### P2 健壮性与维护性
