## H1 修复记录

**问题**：`main.js:2253`（pet:toggle-feature IPC）与 `main.js:3844`（启动路径）调用 `features.startSystemMonitor(...)`，但 `src/features.js` 从未定义该函数（仅导出 `getSystemStats`/`systemStatsToSpeech`）。用户勾选"系统监控播报"后下次启动，`app.whenReady().then()` 内同步抛 TypeError，`unhandledRejection` 兜底吞掉，3844 行之后的初始化（全局热键、首次引导等）全部静默失效。

**方案**：参照 `startClipboardWatch` 模式，在 features.js 第 5 节（系统监控）补 `startSystemMonitor(sendFn, intervalSec)` / `stopSystemMonitor()`：
- 定时轮询 `getSystemStats()`，结果经 `systemStatsToSpeech()` 转台词，非 null 才 `sendFn(msg)`
- 复用已有 `getSystemStats`（PowerShell 查询 CPU/内存），不改其实现
- 间隔参数：main.js 两处调用都传 15（秒），默认参数兜底

**改动文件**：
- [x] `src/features.js`（新增 `startSystemMonitor`/`stopSystemMonitor` + 导出，签名对齐 main.js 调用 `(getStatsFn, sendFn, intervalSec)`；含 30s 播报节流）

**验证**：
- [x] `node --check src/features.js`
- [x] 冒烟（mock stats 函数按 main.js 签名调用）：CPU 95% → 播报 "博士！CPU 已经 95% 了…" PASS；真实 PowerShell 查询也正常（CPU 37%/内存 83% 未超阈值不播报，符合预期）
- [x] 注意：实测发现 mock 外部替换 `mod.getSystemStats` 不影响内部（词法引用），测试须用 getStatsFn 参数注入

**状态**：✅ 已完成（代码 + 冒烟验证，待打包部署）
