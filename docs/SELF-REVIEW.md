# 项目自审：苏苏洛桌宠，向自己学习什么（2026-08-27）

> 目的：梳理本项目自己积累的工程经验（值得固化的模式）与暴露的技术债（待改进项），
> 供后续维护与新特性开发参考。数据基于 2026-08-27 代码基线。

## 一、我们做得好的（值得固化的模式）

1. **防御性工程**：密钥走 safeStorage/DPAPI secrets 模块（config.json 仅回退）；记忆加密 +
   篡改自愈（被改自动恢复、备份为 *.tampered）；蜜标诱饵文件监控——三层防护且都已实测。
2. **"状态低噪诊断"哲学**：行走引擎平时不刷日志，状态**变化**才记一行 + 90 秒无变化告警——
   排查问题时日志里能直接看到最后活跃状态，噪声极小。这个模式值得推广到记忆/语音模块。
3. **消息不丢 + 防抖**：busy 期输入缓冲补发（不吞消息）、主进程 ask 合并缓冲、TTS 会话号
   让旧合成作废——"宁可稍慢，不丢用户输入"的设计取舍很稳。
4. **并发锁**：Agent /chat 串行化链 + 队列深度 429，失败不断链——小改动防住双倍 API 费与
   历史乱序。
5. **渲染链路分层**：GIF/Spine/PSD 三种模式各自独立实现 + 公共行走/交互状态机驱动，
   新皮肤接入成本低（rigger 自动装配）。
6. **人设/记忆/羁绊三层人格化**：台词库按事件/时段分类、规则式事实抽取（宁缺毋滥）、
   羁绊渐进——给"有生命感"留了清晰的扩展点。
7. **全局异常兜底**（v2.6）：主进程 uncaughtException/unhandledRejection 只记日志不弹冻结框——
   把"崩溃可见性"变成"可诊断性"。

## 三、一句话总结（向自己学什么）

**学自己的三层做法**：主流程永远"可诊断"（低噪日志 + 状态变化记录）、敏感数据永远"可自愈"
（加密 + 篡改自动恢复 + 备份留痕）、用户输入永远"不丢"（缓冲补发 + 会话号让位）。
这三条是项目最值得固化的工程气质；技术债集中在"monolith 拆解"与"测试补位"两件事上。
