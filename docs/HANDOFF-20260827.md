### 本机三大坑（反复踩过，务必记住）
1. **CRLF**：Python 打补丁若 `open(p, newline="")` 读入会带 `\r\n`，而锚点串写 `\n` → assert 必失败。
   正确姿势：`open(p, encoding="utf-8").read()`（通用换行），写回用默认 `open(p,"w",encoding="utf-8")`（自动 \r\n）。
   **补丁后必须 grep 验证标记真的写入了**（曾出现"显示成功实际没写入"的假成功）。
2. **GBK 花名**：`tasklist | grep 苏苏` 匹配不到（编码乱）；一律 PowerShell `Get-Process -like`。
   部署目录中文路径偶尔让 git-bash grep 行为异常，必要时改用 python 读文件验证内容。
3. **背景任务超时**：对 userData 大目录（Cache/Network 等 Chromium 缓存）跑 `grep -r` 会卡死几分钟；
   只扫根层 `*.json` 即可。

## 3. 遗留任务（按优先级）

### 3.1 【待观察】左缘微闪的最后嫌疑：出屏钳回高频 setPosition
- 现象残留可能：`walkTick`（40ms 一跳）里的水平兜底
  ```js
  if (charLeft < edgeL) { win.setPosition(fixX, eb.y); ... }  // main.js ~2627
  ```
  该分支的 `logTts` 有 10s 限频（`walk._dbgAt`），**但 setPosition 每个 tick 都会执行**。
  若行走推进恰好把窗口推到边界外几像素，就会形成"推出去→拽回来"的高频拉锯 = 微闪。
- 建议修法（未实施）：加**死区**——`edgeL - charLeft <= 8px` 时不 setPosition，只记录；
  或连续 N tick 才钳一次。改完按 §1 SOP 部署重启，观察 `出屏钳回` 日志频率应显著下降。
- 若死区后仍闪：用 computer-use 截图 + 让用户描述具体场景（贴边瞬间？行走中？GIF 还是 Spine 皮肤？）再定。
